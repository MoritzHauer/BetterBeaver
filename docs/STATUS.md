8. **Unhandled promise rejections on the read paths** — `corepack pnpm lint` reports 10 `@typescript-eslint/no-floating-promises` warnings, all the same shape: `asyncRead().then(setState)` inside a `useEffect` with no rejection handler (`App.tsx` ×7, `BookScreen.tsx:83`, `StatsScreen.tsx:29`, `edit/PrivateEditScreen.tsx:60`). If the underlying IndexedDB or progress-store read rejects — private browsing, quota, a corrupt store — the effect never settles and the screen sits in its empty state with no error, forever. This is the same failure family as the boot-loop crash pinned in [design.md](design.md) ("a malformed content document degrades to a `broken` card, never an exception"). Deliberately left as a warning, not silenced with `void`: each site needs its own decision about what the user should see on failure, which is design work, not a lint fix. **Plus 9 more of the same family that lint no longer reports**: `SessionScreen.tsx` (`:175`, `:234`, `:237`, `:240`, `:290`, `:293`, `:296`, `:371`, `:502`) passes async handlers to `onClick`, which `no-misused-promises` flags and which `eslint.config.js` exempts as accepted React idiom. `no-floating-promises` does **not** cover those — the promise is the arrow's return value, not a statement — so a rejection in the grade path is unguarded and would swallow an SM-2 write silently. 19 sites total. No spec yet.
