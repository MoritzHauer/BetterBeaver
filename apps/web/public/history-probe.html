History probe

Not the app — a bare page testing which kind of history entry survives a real back press on this device. Firefox for Android is reported to skip entries made with pushState when the user presses back, while still honouring them for history.back() — which is why the app's back button works and the system one does not.

The log is saved on this device and survives leaving the page. Do one test at a time, in order, and press back only once per test.

Test A — pushState, no tap

Already done automatically when this page loaded — exactly what the app does at boot. Press back once now, then come back here and read the log.

Test B — pushState, from a tap

Then press back once and return here.

Test C — fragment navigation set by script, from a tap

Not pushState, but still a script changing the location. Press back once and return here.

Test D — a real link to a fragment

Follow #probe-link

No script at all: you follow a link, the browser navigates. Same document, but the entry is a user navigation rather than something code inserted — the closest an SPA gets to an ordinary website. Press back once and return here.

Test E — a real link to another page (control)

Go to probe page 2

A real navigation to a second document, exactly like clicking through any website. This is the positive control: back must work here. If it does not, the problem is not the History API at all.
